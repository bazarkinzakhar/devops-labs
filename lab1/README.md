#лабораторная 1

##часть 1

###плохие практики в dockerfile и их исправление:
1. использование тега latest (from ubuntu:latest). это плохая практика, так как при новой сборке может скачаться другая версия ос исправлено на конкретный легковесный образ (from python:3.9-alpine). результат - образ весит меньше
2. множество слоев из-за разных команд run. каждая команда создает новый слой. исправлено объединением команд через &&
3. запуск от root. по умолчанию контейнеры работают от рута, это небезопасно. исправлено созданием пользователя appuser. в результате контейнер работает с ограниченными правами

###плохие практики при работе с контейнерами:
1. запуск контейнеров с флагом --privileged. это дает контейнеру доступ к макбуку на уровне ядра
2. отсутствие лимитов ресурсов. если запустить контейнер без ограничений по памяти, приложение внутри может забрать всю память хоста

##часть 2

###плохие практики в docker-compose и их исправление:
1. использование тега latest для образов бд и веб. база данных может обновиться на несовместимую версию. исправлено на жесткие версии
2. хардкод паролей прямо в файле. пароль может утечь через гитхаб. исправлено использованием переменной из файла .env, секретов нет в коде
3. отсутствие volumes для базы данных. при пересоздании контейнера данные удалятся. исправлено монтированием named volume

##сетевая изоляция:
чтобы контейнеры поднимались вместе, но не видели друг друга по сети, созданы две кастомные сети: frontend и backend. сервис web подключен только к frontend, а сервис db только к backend. по умолчанию docker помещает всех в одну сеть, где сервисы общаются по именам контейнеров. разнесение по разным сетям изолирует их на уровне сетевых пространств имен docker
