# лабораторная 4

## часть 1
### анализ плохих практик:
1. секреты в env. пароли лежат в открытом коде и легко утекают в логи. исправлено использованием зашифрованного хранилища github secrets.
2. отсутствие фильтров запуска. пайплайн работает даже при правке документации, тратя время. добавлено ограничение через paths-ignore.
3. нефиксированные версии (ubuntu-latest). обновления могут сломать совместимость. исправлено явным указанием ubuntu-22.04.
4. устаревшие экшены (checkout@v2). могут содержать уязвимости. обновлено до версии v4.
5. прямая подстановка секретов в shell. создает риск инъекции команд. исправлено передачей через стандартный ввод (password-stdin).
6. широкие права токена. при компрометации злоумышленник получает полный доступ. исправлено явным указанием permissions: contents: read.

## часть 2
### работа с vault.
почему этот способ красивый:
vault дает централизованное управление с детальным аудитом (видно кто и когда брал секреты). он умеет генерировать временные токены доступа, снижая поверхность атаки
почему переменные ci/cd это плохо:
переменные в github secrets статичны, их сложно ротировать. если злоумышленник взломает пайплайн, он получит доступ сразу ко всем секретам репозитория, тогда как в vault можно тонко настроить политики доступа для каждого этапа
